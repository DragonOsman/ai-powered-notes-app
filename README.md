# DragonOsman AI Notes App

An AI-powered notes application built with Next.js 16, TypeScript, Better Auth, PostgreSQL, MongoDB, and Groq.

The application allows users to manage their notes through a traditional web interface as well as a natural-language AI assistant.

**[Live Demo](https://ai-powered-notes-phi.vercel.app)**

## Features

Users can:

* Create notes
* Read individual notes
* List their notes
* Edit notes
* Delete notes
* Ask the AI assistant to work with their notes
* Generate summaries, titles, todos, and tags from note content

The AI assistant is designed to go beyond generating content. It can perform note operations on behalf of the authenticated user, including creating, reading, editing, and deleting notes.

## Architecture

The application is built with Next.js 16 using the App Router and separates authentication data from application data.

```text
                              ┌─────────────────────┐
                              │     Next.js App     │
                              │   App Router / UI   │
                              └──────────┬──────────┘
                                         │
                    ┌────────────────────┼────────────────────┐
                    │                    │                    │
                    ▼                    ▼                    ▼
            ┌───────────────┐    ┌───────────────┐    ┌───────────────┐
            │  Better Auth  │    │ Note Server   │    │ AI Assistant  │
            │               │    │   Actions     │    │               │
            └───────┬───────┘    └───────┬───────┘    └───────┬───────┘
                    │                    │                    │
                    ▼                    │                    ▼
            ┌───────────────┐            │            ┌───────────────┐
            │ PostgreSQL    │            │            │     Groq      │
            │     Neon      │            │            │      API      │
            └───────────────┘            │            └───────────────┘
                                         │
                                         ▼
                                  ┌───────────────┐
                                  │    MongoDB    │
                                  │   Mongoose    │
                                  └───────────────┘
```

The application uses PostgreSQL and MongoDB for different purposes:

* **PostgreSQL / Neon** stores authentication and account data managed by Better Auth.
* **MongoDB** stores application data such as notes, summaries, tags, and todo items.
* **Mongoose** provides the data modeling layer for MongoDB.
* **Groq** provides the AI inference used by the application's AI assistant.
* **Next.js Server Actions** provide the server-side application operations used by the notes interface and AI assistant.

Database access is performed on the server. The client does not connect directly to either database.

The AI assistant also does not receive unrestricted access to MongoDB. Instead, AI requests are translated into controlled application-level operations. These operations use the same server-side authorization rules as normal note operations.

The application also separates MongoDB's database-level `_id` from the application's `id` representation. MongoDB documents are converted to application-level note objects at the server boundary, keeping MongoDB-specific details out of the UI and React state.

## AI Assistant

The application includes a dedicated AI assistant available throughout the protected portion of the application.

Users can interact with the assistant using natural language to work with their notes.

The assistant can perform operations such as:

* Create a note
* Read or retrieve notes
* Edit an existing note
* Delete a note
* Generate a note summary
* Generate a title
* Generate tags
* Extract todo items

For example, a user can ask the assistant to create a new note from a description, find an existing note, update its content, or summarize several notes.

AI operations are performed through controlled server-side application functions rather than giving the AI model direct access to the database.

This allows the application to maintain the same authentication and authorization rules regardless of whether an operation originates from the normal user interface or the AI assistant.

Destructive operations such as deleting notes can require explicit confirmation from the user before the operation is executed.

Structured responses generated by the AI are validated with dedicated Zod schemas before being passed to application logic.

## Authentication & Security

Authentication is handled by Better Auth with PostgreSQL persistence through Prisma and Neon.

The application supports:

* Email/password authentication
* Email verification
* Password reset
* Magic-link authentication
* Email OTP authentication
* TOTP-based two-factor authentication
* Google OAuth
* GitHub OAuth
* Discord OAuth
* Account linking

Authentication-related data, including users, sessions, linked accounts, verification data, and two-factor authentication data, is managed by Better Auth and stored in PostgreSQL.

Protected routes are checked server-side using the authenticated Better Auth session. Note operations perform their own authorization checks rather than relying solely on client-side route protection.

For note operations, the authenticated user's ID is used together with the note ID when querying MongoDB. This ensures that a user can only access, update, or delete notes belonging to their own account.

The same authorization model applies to AI-initiated note operations. The AI assistant cannot bypass the application's server-side ownership checks.

User input is validated with Zod before being processed or stored. Structured data generated by the AI is also validated against dedicated Zod schemas before being used by the application.

Secrets such as database credentials, OAuth credentials, email credentials, and the Groq API key are stored in environment variables rather than committed to the repository.

## Environment Variables

Create a `.env.local` file in the project root and provide the environment-specific configuration required by the application.

**Never commit `.env.local` or other files containing secrets to the repository.**

| Variable                | Purpose                                                                        |
| ----------------------- | ------------------------------------------------------------------------------ |
| `MONGODB_URI`           | MongoDB connection string used by Mongoose                                     |
| `DATABASE_URL`          | PostgreSQL connection string used by Prisma and Better Auth                    |
| `PGHOST`                | PostgreSQL host used for database connections                                  |
| `PGHOST_UNPOOLED`       | Unpooled PostgreSQL connection host                                            |
| `PGUSER`                | PostgreSQL database username                                                   |
| `PGPASSWORD`            | PostgreSQL database password                                                   |
| `GROQ_API_KEY`          | API key used to access the Groq API                                            |
| `BETTER_AUTH_SECRET`    | Secret used by Better Auth for authentication-related cryptographic operations |
| `BETTER_AUTH_URL`       | Application URL used by Better Auth                                            |
| `GOOGLE_CLIENT_ID`      | Google OAuth client ID                                                         |
| `GOOGLE_CLIENT_SECRET`  | Google OAuth client secret                                                     |
| `GITHUB_CLIENT_ID`      | GitHub OAuth client ID                                                         |
| `GITHUB_CLIENT_SECRET`  | GitHub OAuth client secret                                                     |
| `DISCORD_CLIENT_ID`     | Discord OAuth client ID                                                        |
| `DISCORD_CLIENT_SECRET` | Discord OAuth client secret                                                    |
| `RESEND_SIGNING_SECRET` | Signing secret used to verify Resend webhook requests                          |
| `NEXT_PUBLIC_BASE_URL`  | Public URL of the application                                                  |
| `EMAIL_FROM`            | Sender address used for application emails                                     |
| `EMAIL_SERVER_HOST`     | SMTP server hostname used for application emails                               |
| `EMAIL_SERVER_USER`     | SMTP server username                                                           |
| `EMAIL_SERVER_PASSWORD` | SMTP server authentication password                                            |
| `EMAIL_SERVER_PORT`     | SMTP server port                                                               |

The exact variables required may depend on which authentication providers and email services are enabled.

For local development, create `.env.local` and provide your own development credentials.

For production, configure the corresponding variables through the deployment platform rather than committing them to the repository.
